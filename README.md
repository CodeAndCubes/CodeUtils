# CodeUtils

Служебные мелочи сервера Minecraft 1.7.10, за которыми админ обычно ходит к пяти разным авторам:
рассылка сообщений по расписанию, запуск команд по времени, перезапуск сервера, очистка сущностей,
поведение при полном сервере. Один файл настроек, один таймер и один язык условий на всех.

Мод серверный, клиентской части нет: ванильный клиент заходит без вопросов.

В этой версии работают две подсистемы из пяти: рассылка и планировщик команд. Перезапуск, очистка
сущностей и очередь на вход описаны в файле настроек выключателями, а сам их код приходит следующей
версией.

## Требования

- Minecraft 1.7.10, Forge 10.13.4.1614
- [CodeCore](../CodeCore) 0.1.0 и выше, зависимость обязательная

## Что уже умеет

### Рассылка

Наборы сообщений с собственным интервалом, порядком, получателями и оформлением. Наборов сколько угодно,
имя набора это имя секции в `utils-broadcasts.toml`.

```toml
[sets.links]
enabled = true
intervalSeconds = 1800
firstDelaySeconds = 600
order = "cycle"
whenEmpty = "hold"
sink = "chat"
prefix = "&8[&bСервер&8]&r "
permission = ""
dimensions = []

[[sets.links.messages]]
text = "&7Правила сервера: &b&nнажмите сюда"
hover = "&fОткрыть правила в браузере"
click = "url:https://example.com/rules"
```

- **Порядок.** `cycle` идёт по списку и возвращается в начало, `random` берёт случайное каждый раз,
  `shuffle` выдаёт список без повторов и перемешивает заново.
- **Получатели.** `permission` и `dimensions` сужают выборку по И, пустые значения означают всех онлайн.
- **Пустой сервер.** `hold` не шлёт и не двигает указатель, поэтому первый зашедший игрок увидит первую
  подсказку, а не седьмую. `skip` двигает указатель, `log` пишет строку в лог. Во всех трёх случаях
  дедлайн переставляется, и десять пустых интервалов не выстрелят очередью после входа игрока.
- **Щелчок и наведение.** `click` пишется как `url:<адрес>`, `run:<команда>` или `suggest:<строка>`.
  Команда из `run:` выполняется от имени щёлкнувшего и с его правами. Ключ `parts` даёт разным словам
  одной строки разные щелчки; собственный `text` сообщения идёт первой частью. Опечатка в приставке
  щелчка не роняет набор: сообщение уходит без щелчка, а в лог уходит одна строка с именем набора и
  номером сообщения.
- **Приёмник.** Встроены `chat` и `log`. Незнакомое имя приёмника выключает набор с одной строкой в логе
  при старте, а не на каждом срабатывании.

Титров и строки над хотбаром в 1.7.10 нет: пакета титров в протоколе не существует, а `S02PacketChat`
несёт только компонент и признак «чат или система». Приёмник, который их обещает, обещал бы невозможное.

### Планировщик команд

```toml
[jobs.night-clean]
enabled = false
command = "codeutils clean drops"
everySeconds = 0
at = ["04:00"]
as = "console"
onFailure = "log"
retrySeconds = 60
retries = 0
catchUpSeconds = 0
```

- **Расписание.** `everySeconds` и список моментов `at` работают вместе. Часовой пояс берётся из ключа
  `timezone` файла `utils.toml`.
- **Отправитель.** `console` это сам сервер. `commandblock` это поддельный командный блок на точке
  спавна: ванильное правило `commandBlockOutput = false` снимает оповещение операторов о выполненной
  команде, и ночное задание перестаёт светиться всем. `player:<ник>` берёт игрока онлайн, а если его нет,
  срабатывает политика отказа.
- **Отказ.** Игра отвечает числом удачных исполнений, а не признаком успеха, поэтому «не сработало»
  здесь означает «вернулось не больше нуля». Заводская политика `log` стоит одну строку в логе, `retry`
  повторяет через `retrySeconds` до `retries` раз, `quiet` молчит.
- **Пропущенные моменты.** Момент, попавший между двумя показаниями часов такта, срабатывает ровно один
  раз, сколько бы ни длился подвисший тик. Момент, пришедшийся на время остановки сервера, догоняется
  только внутри окна `catchUpSeconds`; заводской ноль означает, что не догоняется. Интервал при этом
  сгорает: десять минут простоя при `everySeconds = 60` дают одну команду, а не десять.

## Файлы настроек

Всё лежит в `config/code/utils/`.

| Файл | Что в нём | Когда создаётся |
|---|---|---|
| `utils.toml` | часовой пояс, выключатели подсистем, что писать в лог | всегда |
| `utils-commands.toml` | какие корни команд живут и под какими именами | всегда |
| `utils-broadcasts.toml` | наборы рассылки | при `on.broadcasts = true` |
| `utils-jobs.toml` | задания планировщика | при `on.jobs = true` |

Выключенная подсистема не создаёт своего файла, не подписывается на события и не занимает ветку такта.
Существующий файл при выключении остаётся на диске нетронутым, и включение возвращает прежние настройки.

Своих секций в главном файле `config/code/config.toml` мод не объявляет: туда уезжает настройка, общая
для нескольких модов, а у CodeUtils такой нет ни одной. Читает он оттуда две вещи, которые ядро уже
собрало: `audit.utils` решает, писать ли строку о каждом выполненном задании, а имя сервера идёт в
стартовую сводку.

Постоянного состояния мод не хранит вовсе: ни файла в папке мира, ни json. Указатель рассылки и отметки
заданий живут в памяти и умирают вместе с сервером.

## Команды

| Команда | Узел | Что делает |
|---|---|---|
| `/codeutils status` | `codeutils.admin.status` | что включено, сколько наборов и заданий, ближайший момент |
| `/codeutils reload` | `codeutils.admin.reload` | перечитать файлы настроек, переставить дедлайны |
| `/codeutils broadcast <набор>` | `codeutils.admin.broadcast` | отправить следующее сообщение набора сейчас |
| `/codeutils jobs` | `codeutils.admin.jobs` | список заданий с ближайшим моментом |
| `/codeutils jobs run <имя>` | `codeutils.admin.jobs` | выполнить задание сразу, не сбивая расписание |
| `/broadcast <текст>` | `codeutils.admin.broadcast` | разовое сообщение всем онлайн |

Каждый корень выключается и переименовывается в `utils-commands.toml`. Выключенный корень не
регистрируется вовсе, и его имя остаётся свободным для чужого мода. Список алиасов заменяет заводской
целиком.

Полный перечень узлов в [perms.md](perms.md).

`/codeutils reload` перечитывает файлы и переставляет дедлайны. Смена выключателя `[on]` и правка
`utils-commands.toml` ждут перезапуска сервера: корни команд сервер получает один раз при старте, а
подсистема, снятая при старте, файла своего не открывала.

## Швы для чужих модов

Артефакт `codeutils-api` чистый: ни одного типа Minecraft, ни одной ссылки на внутренние пакеты. Против
него компилируются чужие моды.

```java
CodeUtilsApi.registry()
    .addSink("discord", (recipients, message) -> bridge.post(message.flat()));
CodeUtilsApi.registry()
    .addCondition("event-running", snapshot -> events.anyLive());
CodeUtilsApi.registry()
    .addRunner("mine", ticket -> RunOutcome.ran(doItMyWay(ticket.command())));
```

Заявки принимаются в фазе init своего мода. В конце постинициализации реестр замерзает, потому что сразу
после этого CodeUtils разрешает имена из файлов настроек и говорит в лог про каждое незнакомое. Заявка
после заморозки отклоняется исключением с текстом о фазе, а не теряется молча.

| Шов | Метод | Встроенные |
|---|---|---|
| `BroadcastSink` | `send(List<PlayerRef>, Message)` | `chat`, `log` |
| `RunCondition` | `boolean allows(ServerSnapshot)` | ключи блока `when` |
| `CommandRunner` | `RunOutcome run(CommandTicket)` | `server` |

## Общий блок условий

У набора рассылки и у задания один и тот же блок `when` с одними и теми же ключами, поэтому админ учит
его один раз.

```toml
[sets.tips.when]
minPlayers = 1
maxPlayers = 0
between = ""
days = []
maxTickMillis = 0
custom = []
```

Ключи соединяются по И, пустой блок означает «всегда». Окно `between` можно писать через полночь:
`"23:00-02:00"` при 00:30 выполнено. Имя из `custom`, которого нет в реестре, названо в логе один раз при
старте и считается невыполненным условием: расписание с опечаткой молчит, а не срабатывает мимо
задуманного.

## Один такт на весь мод

Все подсистемы, которые считают время, будит один секундный такт поверх планировщика ядра. Своего потока
мод не заводит.

Такт сравнивает не «сколько тиков прошло», а два показания часов: предыдущее и нынешнее. Момент
срабатывает, когда он попал в промежуток между ними, поэтому сервер, застрявший на десять секунд,
отработает всё, что пришлось на эти десять секунд, ровно по одному разу, а не потеряет и не повторит.

## Сборка

```
./gradlew spotlessApply build
```

На выходе `CodeUtils-0.1.0-server.jar` для сервера и универсальный `CodeUtils-0.1.0.jar` для dev-запусков.
Артефакт `codeutils-api` собирается тем же прогоном.

Нужен JDK 25 для демона Gradle (версию задаёт `gradle/gradle-daemon-jvm.properties`), байткод при этом
остаётся Java 8. `--rerun-tasks` не использовать: он сбрасывает распаковку Minecraft. Для повторного
прогона тестов `./gradlew cleanTest test`.
