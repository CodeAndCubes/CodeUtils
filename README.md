# CodeUtils

Служебные мелочи сервера Minecraft 1.7.10, за которыми админ обычно ходит к пяти разным авторам:
рассылка сообщений по расписанию, запуск команд по времени, перезапуск сервера, очистка сущностей,
поведение при полном сервере. Один файл настроек, один таймер и один язык условий на всех.

Мод серверный, клиентской части нет: ванильный клиент заходит без вопросов.

Работают все пять подсистем. Очередь на вход по умолчанию снята: ей нужен `max-players` выше самой
верхней ступени, и без правки `server.properties` она не сделает ничего.

## Требования

- Minecraft 1.7.10, Forge 10.13.4.1614
- [CodeCore](https://github.com/CodeAndCubes/CodeCore) 0.1.0 и выше, зависимость обязательная

## Установка

| Файл | Куда |
|---|---|
| `CodeUtils-1.0.0-server.jar` | `mods/` сервера |
| `codeutils-1.0.0-api.jar` | тем, кто пишет своё условие или задачу: компиляция, на сервер не нужен |
| `codeutils-1.0.0-dev.jar` | им же: deobf-версия для dev-запусков |

Клиентской части нет: ванильный клиент заходит на сервер без этого мода. Ставится после CodeCore.
Java 8 или 17 и 21 под lwjgl3ify, Minecraft 1.7.10, Forge 10.13.4.1614.

## Что уже умеет

### Рассылка

Наборы сообщений с собственным интервалом, порядком, получателями и оформлением. Наборов сколько угодно,
имя набора это имя секции в `utils-broadcasts.toml`.

```toml
[sets.links]
enabled = true
intervalSeconds = 1800
firstDelaySeconds = 600
order = "cycle"
whenEmpty = "hold"
sink = "chat"
prefix = "&8[&bСервер&8]&r "
permission = ""
dimensions = []

[[sets.links.messages]]
text = "&7Правила сервера: &b&nнажмите сюда"
hover = "&fОткрыть правила в браузере"
click = "url:https://example.com/rules"
```

- **Порядок.** `cycle` идёт по списку и возвращается в начало, `random` берёт случайное каждый раз,
  `shuffle` выдаёт список без повторов и перемешивает заново.
- **Получатели.** `permission` и `dimensions` сужают выборку по И, пустые значения означают всех онлайн.
- **Пустой сервер.** `hold` не шлёт и не двигает указатель, поэтому первый зашедший игрок увидит первую
  подсказку, а не седьмую. `skip` двигает указатель, `log` пишет строку в лог. Во всех трёх случаях
  дедлайн переставляется, и десять пустых интервалов не выстрелят очередью после входа игрока.
- **Щелчок и наведение.** `click` пишется как `url:<адрес>`, `run:<команда>` или `suggest:<строка>`.
  Команда из `run:` выполняется от имени щёлкнувшего и с его правами. Ключ `parts` даёт разным словам
  одной строки разные щелчки; собственный `text` сообщения идёт первой частью. Опечатка в приставке
  щелчка не роняет набор: сообщение уходит без щелчка, а в лог уходит одна строка с именем набора и
  номером сообщения.
- **Приёмник.** Встроены `chat` и `log`. Незнакомое имя приёмника выключает набор с одной строкой в логе
  при старте, а не на каждом срабатывании.

Титров и строки над хотбаром в 1.7.10 нет: пакета титров в протоколе не существует, а `S02PacketChat`
несёт только компонент и признак «чат или система». Приёмник, который их обещает, обещал бы невозможное.

### Планировщик команд

```toml
[jobs.night-clean]
enabled = false
command = "codeutils clean drops"
everySeconds = 0
at = ["04:00"]
as = "console"
runner = "server"
onFailure = "log"
retrySeconds = 60
retries = 0
catchUpSeconds = 0
```

- **Расписание.** `everySeconds` и список моментов `at` работают вместе. Ноль в `intervalSeconds` набора
  и в `everySeconds` задания снимает расписание, а не означает «каждую секунду»: набор после этого уходит
  только по `/codeutils broadcast <набор>`, задание только по `/codeutils jobs run <имя>`. Часовой пояс берётся из ключа
  `timezone` файла `utils.toml`.
- **Отправитель.** `console` это сам сервер. `commandblock` это поддельный командный блок на точке
  спавна: ванильное правило `commandBlockOutput = false` снимает оповещение операторов о выполненной
  команде, и ночное задание перестаёт светиться всем. `player:<ник>` берёт игрока онлайн, а если его нет,
  срабатывает политика отказа.
- **Исполнитель.** Ключ `runner` называет шов, которым выполняется строка задания. Встроен `server`, он
  отдаёт её командам сервера. Опечатка в имени выключает задание одной строкой в лог при старте и не
  откатывается на `server`: чужой исполнитель мог быть обёрткой с проверкой, и тихое выполнение команды
  напрямую хуже неработающего задания.
- **Отказ.** Игра отвечает числом удачных исполнений, а не признаком успеха, поэтому «не сработало»
  здесь означает «вернулось не больше нуля». Заводская политика `log` стоит одну строку в логе, `retry`
  повторяет через `retrySeconds` до `retries` раз, `quiet` молчит.
- **Пропущенные моменты.** Момент, попавший между двумя показаниями часов такта, срабатывает ровно один
  раз, сколько бы ни длился подвисший тик. Момент, пришедшийся на время остановки сервера, догоняется
  только внутри окна `catchUpSeconds`; заводской ноль означает, что не догоняется. Интервал при этом
  сгорает: десять минут простоя при `everySeconds = 60` дают одну команду, а не десять.

### Перезапуск без дюпа

Дюп при остановке берётся из промежутка между записью файла игрока и записью мира. Порядок шагов здесь
и есть подсистема:

1. предупреждения по списку `warnings.seconds`;
2. вход закрывается за `closeDoorSeconds`;
3. каждому игроку закрывается открытое окно, и сразу за этим идёт кик за `kickSeconds`;
4. пауза `settleTicks`;
5. проверка, что список игроков пуст;
6. шаги чужих модов фазы `BEFORE_SAVE`;
7. запись данных игроков, затем запись всех миров;
8. шаги фазы `AFTER_SAVE`;
9. остановка.

Окно закрывается до кика, а не после: ванильный выход игрока пишет его данные и не трогает открытый
контейнер, а предмет на курсоре и содержимое сетки крафта в этот момент не в инвентаре.

Шаги чужих модов встают в четыре точки: `BEFORE_DOOR` перед вторым шагом, `BEFORE_KICK` перед третьим,
`BEFORE_SAVE` шестым и `AFTER_SAVE` восьмым. Первые две дают последнюю возможность потрогать игроков: до
закрытия двери они ещё заходят, до кика они ещё в мире.

```toml
[schedule]
enabled = false
at = ["06:00"]
days = []

[steps]
closeDoorSeconds = 30
kickSeconds = 5
settleTicks = 20
savePlayers = true
saveWorlds = true
```

- **Момент расписания это время остановки.** `at = ["06:00"]` означает, что в шесть утра сервер уже
  остановлен; отсчёт с предупреждениями начинается раньше.
- **Окно остановки.** С начала кика и до остановки такт мода стоит: задания, рассылка и очистка в этом
  окне не работают, дверь не открывается, `/restart cancel` отклоняется ключом `too_late`. Отмена до
  кика возвращает дверь и расписание и говорит об этом всем онлайн.
- **Проскочивший игрок.** Список игроков после паузы не пуст, кик повторяется один раз с записью ников
  в лог, дальше остановка идёт по порядку: сервер без остановки хуже остановки с жалобой в логе.
- **Обратно мод сервер не поднимает.** Процесс поднимает обёртка: служба systemd, pm2 или цикл в
  bat-файле. Выполнение внешней команды операционной системы из мода это дыра в правах и разное
  поведение на Windows и Linux.

### Очистка сущностей

```toml
[rules.drops]
enabled = true
types = ["@item", "@xp"]
dimensions = []
minAgeSeconds = 60
intervalSeconds = 900
worldThreshold = 0
chunkThreshold = 0
warnSeconds = [30, 10]
warnSink = "chat"
maxRemovals = 0
ignoreGuards = []
```

- **Язык типов.** Точное имя из игры (`Item`, `Zombie`), хвост со звёздочкой (`Thermal*`), группа с
  собачкой (`@item`, `@xp`, `@hostile`, `@passive`, `@projectile`, `@vehicle`, `@all`) и минус впереди,
  который вычитает из уже набранного. Список читается слева направо, поэтому `["-Zombie", "@hostile"]`
  зомби оставляет, а `["@hostile", "-Zombie"]` снимает.
- **Восемь защит.** `named`, `tamed`, `leashed`, `boss`, `persistent`, `carrying`, `ridden`, `hanging`.
  Снимаются только явным именем в `ignoreGuards` конкретного правила, и снятая защита означает, что
  правило удалит и названную бирку, и чужого прирученного волка. Игроки не удаляются вовсе и в список
  защит не входят.
- **Три поведения из двух чисел.** Только `intervalSeconds` даёт проход по расписанию; вместе с порогом
  проход идёт по расписанию, а удаление только при превышении; только порог означает счёт по такту раз в
  тридцать секунд и удаление при превышении.
- **Проход в два шага.** Сначала перебор со сбором подходящих и подсчётом по чанкам, потом удаление по
  собранному: править список загруженных сущностей во время обхода нельзя. Проход дольше
  `log.slowPassMillis` получает строку в лог с числом просмотренных и снятых.

### Мягкие потолки слотов и очередь

Настоящей очереди, в которой клиент висит в подключении и видит свой номер, на 1.7.10 без прокси или
ASM не бывает: ванильная проверка «сервер полон» сидит в `ServerConfigurationManager.allowUserToConnect`,
событий Forge в том пути нет, а пакета с номером очереди в протоколе не существует. Поэтому админ ставит
`max-players` заведомо высоким, а настоящие потолки задаёт мод.

```toml
[slots]
base = 60

[slots.tiers.vip]
node = "codeutils.slots.vip"
slots = 70

[queue]
enabled = true
policy = "by-permission"
ticketSeconds = 180
holdSeconds = 15
retryHintSeconds = 20
```

- **Ступени.** Игрок без ступени проходит, пока онлайн меньше `slots.base`, со ступенью `vip` пока
  меньше её потолка. Узел ступени задаёт админ, поэтому ступени садятся на уже существующие узлы сервера
  без переименований. Игрок с несколькими ступенями получает самую высокую.
- **Очередь.** Отказ уходит с номером: билет заводится на время первого стука, порядок считается внутри
  ступени, старшая ступень обслуживается раньше. Повторный стук обновляет срок и номера не меняет.
  Билет живёт `ticketSeconds` без стука. Освободившийся слот держится `holdSeconds` за головой очереди.
- **Вне главного потока.** Решение принимается на потоке сети, до того как игрок попал в мир: его файл
  не переписывается и сообщений о входе нет. Онлайн мод считает своим счётчиком, который двигают события
  входа и выхода, а мир из решения не трогается вовсе.
- **Чего нет.** Клиентской части с экраном отказа, обратным отсчётом и автоматическим повторным стуком.
  Без неё игрок стучится руками, и текст отказа прямо просит его об этом через `retryHintSeconds`.

## Файлы настроек

Всё лежит в `config/code/utils/`.

| Файл | Что в нём | Когда создаётся |
|---|---|---|
| `utils.toml` | часовой пояс, выключатели подсистем, что писать в лог | всегда |
| `utils-commands.toml` | какие корни команд живут и под какими именами | всегда |
| `utils-broadcasts.toml` | наборы рассылки | при `on.broadcasts = true` |
| `utils-jobs.toml` | задания планировщика | при `on.jobs = true` |
| `utils-restart.toml` | расписание остановки, предупреждения, порядок шагов | при `on.restart = true` |
| `utils-cleanup.toml` | правила очистки сущностей | при `on.cleanup = true` |
| `utils-queue.toml` | потолки слотов и очередь | при `on.queue = true` |

Выключенная подсистема не создаёт своего файла, не подписывается на события и не занимает ветку такта.
Существующий файл при выключении остаётся на диске нетронутым, и включение возвращает прежние настройки.

Своих секций в главном файле `config/code/config.toml` мод не объявляет: туда уезжает настройка, общая
для нескольких модов, а у CodeUtils такой нет ни одной. Читает он оттуда две вещи, которые ядро уже
собрало: `audit.utils` решает, писать ли строку о каждом выполненном задании, а имя сервера идёт в
стартовую сводку.

Постоянного состояния мод не хранит вовсе: ни файла в папке мира, ни json. Указатель рассылки, отметки
заданий и билеты очереди живут в памяти и умирают вместе с сервером. Билет, переживший перезапуск, был
бы билетом в очередь на пустой сервер.

## Команды

| Команда | Узел | Что делает |
|---|---|---|
| `/codeutils status` | `codeutils.admin.status` | что включено, сколько наборов и заданий, ближайший момент |
| `/codeutils reload` | `codeutils.admin.reload` | перечитать файлы настроек, переставить дедлайны |
| `/codeutils broadcast <набор>` | `codeutils.admin.broadcast` | отправить следующее сообщение набора сейчас |
| `/codeutils jobs` | `codeutils.admin.jobs` | список заданий с ближайшим моментом |
| `/codeutils jobs run <имя>` | `codeutils.admin.jobs` | выполнить задание сразу, не сбивая расписание |
| `/codeutils clean [правило] [now]` | `codeutils.admin.clean` | посчитать и показать, `now` выполняет проход |
| `/codeutils queue` | `codeutils.admin.queue` | ступени, потолки, кто в очереди и с какого времени |
| `/codeutils restart <срок>` | `codeutils.admin.restart` | то же, что корень `/restart` |
| `/restart <срок>` | `codeutils.admin.restart` | поставить, снять (`cancel`), начать сейчас (`now`) |
| `/broadcast <текст>` | `codeutils.admin.broadcast` | разовое сообщение всем онлайн |

Каждый корень выключается и переименовывается в `utils-commands.toml`. Выключенный корень не
регистрируется вовсе, и его имя остаётся свободным для чужого мода. Список алиасов заменяет заводской
целиком.

Полный перечень узлов в [perms.md](perms.md).

`/codeutils reload` перечитывает файлы и переставляет дедлайны. Смена выключателя `[on]` и правка
`utils-commands.toml` ждут перезапуска сервера: корни команд сервер получает один раз при старте, а
подсистема, снятая при старте, файла своего не открывала.

## Швы для чужих модов

Артефакт `codeutils-api` чистый: ни одного типа Minecraft, ни одной ссылки на внутренние пакеты. Против
него компилируются чужие моды.

```java
CodeUtilsApi.registry()
    .addSink("discord", (recipients, message) -> bridge.post(message.flat()));
CodeUtilsApi.registry()
    .addCondition("event-running", snapshot -> events.anyLive());
CodeUtilsApi.registry()
    .addRunner("mine", ticket -> RunOutcome.ran(doItMyWay(ticket.command())));
```

Заявки принимаются в фазе init своего мода. В конце постинициализации реестр замерзает, потому что сразу
после этого CodeUtils разрешает имена из файлов настроек и говорит в лог про каждое незнакомое. Заявка
после заморозки отклоняется исключением с текстом о фазе, а не теряется молча.

| Шов | Метод | Встроенные |
|---|---|---|
| `BroadcastSink` | `send(List<PlayerRef>, Message)` | `chat`, `log` |
| `RunCondition` | `boolean allows(ServerSnapshot)` | ключи блока `when` |
| `CommandRunner` | `RunOutcome run(CommandTicket)` | `server` |
| `CleanupGuard` | `boolean protects(EntityView)` | восемь защит |
| `RestartStep` | `phase()`, `name()`, `run(RestartPlanView)` | нет |
| `QueuePolicy` | `QueueDecision decide(QueueRequest, QueueState)` | `by-permission` |

Четыре шва выбираются по имени там, где ими пользуются: `sink` набора, `custom` блока условий, `runner`
задания и `queue.policy`. Защиты очистки спрашиваются все сразу, шаги остановки выполняются все в своей
точке, поэтому имени они не выбирают.

## Общий блок условий

У набора рассылки, задания, правила очистки и расписания перезапуска один и тот же блок `when` с одними
и теми же ключами, поэтому админ учит его один раз.

```toml
[sets.tips.when]
minPlayers = 1
maxPlayers = 0
between = ""
days = []
maxTickMillis = 0
custom = []
```

Ключи соединяются по И, пустой блок означает «всегда». Окно `between` можно писать через полночь:
`"23:00-02:00"` при 00:30 выполнено. Имя из `custom`, которого нет в реестре, названо в логе один раз при
старте и считается невыполненным условием: расписание с опечаткой молчит, а не срабатывает мимо
задуманного.

## Один такт на весь мод

Все подсистемы, которые считают время, будит один секундный такт поверх планировщика ядра. Своего потока
мод не заводит.

Такт сравнивает не «сколько тиков прошло», а два показания часов: предыдущее и нынешнее. Момент
срабатывает, когда он попал в промежуток между ними, поэтому сервер, застрявший на десять секунд,
отработает всё, что пришлось на эти десять секунд, ровно по одному разу, а не потеряет и не повторит.

## Сборка

```
./gradlew spotlessApply build
```

На выходе `CodeUtils-0.1.0-server.jar` для сервера и универсальный `CodeUtils-0.1.0.jar` для dev-запусков.
Артефакт `codeutils-api` собирается тем же прогоном.

Нужен JDK 25 для демона Gradle (версию задаёт `gradle/gradle-daemon-jvm.properties`), байткод при этом
остаётся Java 8. `--rerun-tasks` не использовать: он сбрасывает распаковку Minecraft. Для повторного
прогона тестов `./gradlew cleanTest test`.
